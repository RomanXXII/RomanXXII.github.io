AI + Binary Analysis LLM-Based Binary Similarity Research Explored cybersecurity applications for large language models by investigating whether they could identify meaningful similarity and potentially malicious behavioral patterns within lifted binary code represented as High-Level Intermediate Language (HLIL) generated through Binary Ninja.
  • Cross-architecture analysis
  • Optimization-level comparisons
  • Prompt engineering
  • Nondeterminism studies

The project was motivated by modern cybersecurity challenges surrounding generated and obfuscated malicious code. As attackers gain increasing access to AI-assisted tooling, malicious behavior can often be disguised beneath structurally different implementations, making low-level manual analysis increasingly difficult and time-intensive for human analysts.

Using Python-based analysis pipelines, I developed a block-comparison workflow that divided HLIL files into manageable sections and compared them through repeated LLM similarity scoring. Earlier stages of the project experimented with whole-file comparisons and normalization pipelines before transitioning toward pairwise block analysis to better manage model context limitations and improve scoring consistency.

Testing included binaries compiled across multiple architectures and optimization levels, including ARM and x86 targets alongside O2 and O3 compiler optimizations, in order to evaluate whether meaningful behavioral alignment could still be detected despite significant structural and compiler-driven changes in the resulting binaries.

Multiple model architectures were explored throughout development, including gpt-oss:20b, llama3.3:70b, and gpt-oss:120b. Supporting Python scripts generated similarity matrices, heatmaps, diagonal alignment statistics, and deterministic scoring metrics to analyze model consistency, context sensitivity, and nondeterministic behavior across repeated runs.

Autonomous Systems + Infrastructure Autonomous Driving Data & Annotation Platform Contributed to a containerized data and annotation pipeline designed for autonomous-driving computer vision workflows using OpenPilot and CVAT-based labeling infrastructure.
  • CVAT integration
  • Docker Compose
  • FastAPI + React
  • Human-in-the-loop labeling

The platform was designed to ingest, process, manage, and annotate driving data for future machine learning and human-review workflows. The system integrated CVAT labeling, artifact storage, route downloading, dataset export workflows, and distributed worker infrastructure within a unified containerized environment.

My work focused heavily on the CVAT integration layer, including running and configuring CVAT containers, interacting with the CVAT API through Python automation scripts, creating task-batching workflows, exporting annotations as COCO JSON, and testing annotation pipelines against live CVAT deployments. I also worked with model-assisted labeling workflows using HuggingFace object-detection models including RT-DETRv2.

The annotation pipeline followed a human-in-the-loop workflow: upload image batches into CVAT tasks, run automated annotation passes, route annotations through human review, export structured labels, and support future retraining workflows for autonomous-driving models. The project explored how automation and human validation could be combined to improve annotation scalability and dataset generation efficiency for autonomous-driving research.

The broader system architecture used Docker Compose orchestration alongside FastAPI, React, PostgreSQL, MinIO object storage, and asynchronous worker containers responsible for downloading, processing, exporting, and managing OpenPilot driving-route data.

Applied Security Secure Peer-to-Peer Messaging Tool The final implementation used PyNaCl Box encryption to establish shared secrets through elliptic-curve Diffie-Hellman-style exchange while verifying peer authenticity through signed public keys.
  • PyNaCl encryption
  • Signed public keys
  • Socket transport
  • Tkinter GUI

Additional work included encrypted message transport, nonce handling, socket communication management, GUI development with Tkinter, and plaintext-versus-ciphertext visualization for debugging and educational analysis.

The project strengthened my understanding of how cryptographic concepts translate into real-world implementation decisions, particularly surrounding trust establishment, authentication, secure communication channels, and protocol behavior under practical constraints.

Protocol pseudocode

Open full pseudocode 
START SECURE CHAT SESSION

Peer A and Peer B each generate encryption and signing key pairs.
Each peer signs its own encryption public key.
Each peer sends the other its encryption public key, signature, and signing public key.

VERIFY PEER IDENTITY

On receipt of peer key material:
  peer_encryption_public_key = received encryption public key
  peer_signature = received signature
  peer_signing_public_key = received signing public key

Verify the peer signature over the received encryption public key.
If verification fails, terminate the connection.
If verification succeeds, continue secure setup.

DERIVE SHARED SECRET

Each peer combines its encryption private key with the peer encryption public key.
Both peers independently derive the same shared secret without sending it directly.

SEND ENCRYPTED MESSAGE

When the user sends a message:
  plaintext = user input
  nonce = GenerateRandomNonce()
  ciphertext = Encrypt(shared_secret, nonce, plaintext)
  packet = MessageType || MessageLength || ciphertext
  send packet over socket

RECEIVE ENCRYPTED MESSAGE

When a packet is received:
  read message type
  read message length
  read ciphertext bytes
  plaintext = Decrypt(shared_secret, ciphertext)
  display plaintext and ciphertext separately

SECURITY PROPERTIES DEMONSTRATED

The shared secret is never transmitted directly.
Fresh nonces prevent identical messages from producing identical ciphertext.
Signed public keys help prevent unauthorized key substitution.
